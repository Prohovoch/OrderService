# OrderService — Telegram Bot Backend (MVP)

Данный проект представляет собой **MVP (Minimum Viable Product)** бэкенд-сервиса для клиентского Telegram-бота, обрабатывающего заказы. 

Основная цель проекта — демонстрация и исследование архитектурного подхода **Vertical Slice Architecture (Вертикальные срезы)** в связке с паттерном **REPR (Request-Endpoint-Response)** в экосистеме .NET 10+.

---

## 🏗️ Архитектура и подходы

В отличие от классической многослойной архитектуры (Clean/Onion), где код разделен по техническим слоям (Controllers, Services, Repositories), этот проект построен вокруг **бизнес-фич**:

1. **Vertical Slice Architecture:** Каждая папка внутри проекта инкапсулирует в себе всю логику конкретной бизнес-фичи (от валидации и работы с БД до эндпоинта). Это минимизирует связность кода (coupling) и упрощает изменения.
2. **REPR Pattern:** Архитектурный паттерн, утверждающий, что веб-эндпоинт должен принимать строго один тип запроса (`Request`) и возвращать строго один тип ответа (`Response`). Реализовано с помощью легковесных эндпоинтов.

### Полезные материалы по подходам:
* [Vertical Slice Architecture — Jimmy Bogard](https://www.jimmybogard.com/vertical-slice-architecture/) — детальный разбор концепции от автора подхода.
* [REPR Pattern & FastEndpoints](https://fast-endpoints.com) — современная альтернатива классическим контроллерам, оптимизированная под REPR.
* [Embrace Api Endpoints](https://ardalis.com/mvc-controllers-are-dinosaurs-embrace-api-endpoints/) -  REPR pattern

## 🚀 Как запустить проект локально

Проект полностью контейнеризирован. Для запуска вам понадобятся установленные **Docker** и **Docker Compose**.

### 1. Клонирование репозитория
```bash
git clone https://github.com/Prohovoch/OrderService
cd OrderService
```

### 2. Настройка окружения
Создайте файл `.env` в корневой папке проекта рядом с `docker-compose.yml` и заполните его вашими конфигурационными данными. Пример находится в файле .env.example
```bash
PORT=""
PGDB_PORT=""
PGDB_NAME=""
PGDB_USER=""
PGDB_PASSWORD=""

# Переменные интеграции Telegram-бота
BOTAPIHEADER=X-Bot-Api-Key
TGBOT_API=your_telegram_bot_secret_token_123
TGADMIN_ID=123456789
```

### 3. Сборка и запуск инфраструктуры
Выполните команду для сборки образов и поднятия контейнеров в фоновом режиме:
```bash
docker compose up -d --build
```
*Инфраструктура автоматически развернет PostgreSQL, применит встроенный механизм автомиграций (`MigrateAsync`) при старте приложения и поднимет бэкенд.*

### 4. Проверка работы (Интерактивная документация)
После успешного старта документация API доступна в вашем браузере по адресу:
👉 **[http://localhost:8080/swagger]**.

На данный момент используется устаревший swagger. Дополнительно выявлены проблемы. См.  *Планы*.

## 🛠️ Текущий статус и технический долг (Известные изъяны)
Так как проект находится в стадии **MVP**, приоритетом являлась скорость проверки гипотез и Time-to-Market. В архитектуру сознательно заложен контролируемый технический долг, который будет закрыт на следующих этапах разработки. Такое как исправление выявленных изъянов с помощью ручного тестирования.

* **[ ] Исправление ошибок валидации (Bugfix):** Корректировка работы регулярных выражений для номеров телефонов и устранение проблем с кастомно разработанном middleware в DI-контейнере.
